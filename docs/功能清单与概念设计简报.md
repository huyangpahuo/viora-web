## 一、产品是什么

**Viora Plugins** 是一个**风格插件的视觉发现画廊 + 作者社区**。

- Viora 是一款桌面端图像风格化工具(类似滤镜/风格迁移),"插件"即一种艺术风格效果(动漫、油画、水彩、赛博朋克、像素艺术等,共 20 个官方大类)。
- 网站的核心体验:**像逛 Pinterest 一样浏览插件的效果图**,发现喜欢的风格,点进详情看"转换前 → 转换后"的对比,然后下载或在客户端里安装。
- 同时它是一个**开放的多作者平台**:任何作者注册账号、关联 GitHub 后即可发布自己的插件,所有作者的插件在站内**一律平等展示**(没有"官方/社区"的分级概念)。
- 语言:全站中文界面(插件名/介绍支持中英双语)。

**目标用户**:使用 Viora 的创作者、喜欢风格化图像的普通用户、发布插件的作者。

## 二、技术栈与硬约束(概念图不必画出技术细节,但布局需可落地)

- Next.js 16(App Router)+ TypeScript + Tailwind CSS v4 + shadcn/ui + Supabase(Auth/PostgreSQL)+ Vercel。
- 图标体系:Font Awesome。
- 站点当前为**纯暗色主题**(没有浅色模式)。
- **数据真实性红线**:不得出现虚构的评分星级、下载量、评论数、点赞数或"AI 生成的假效果图"冒充插件效果。当前数据库中没有评分/下载量数据,概念图若展示此类元素,请明确标注为"未来功能占位"。

## 四、逐模块功能详述

### 4.1 画廊首页(核心页面)

- **Pinterest 式非等高瀑布流**:桌面 4–5 列、平板 3 列、手机 2 列;卡片高度随图片自然比例变化。
- **懒加载**:图片未加载时显示低饱和分类色占位块(宽高比锁定,不跳动),加载完成后淡入;首屏前 6 张立即加载。
- **搜索**:全局搜索框(顶栏),匹配名称(中英)、介绍、标签、插件 ID、分类;关键词保留在 URL 中,结果可分享。
- **分类筛选**:横向滚动的分类胶囊条(全部 / 动漫 / 插画 / 油画 / 水彩 / 素描 / 版画 / 像素艺术 / 复古胶片 / 3D 立体 / 赛博朋克 / 霓虹灯光 / 手工艺 / 纸艺纸雕 / 拼贴混合 / 摄影暗房 / 玻璃马赛克 / 金属质感 / 光影粒子 / 国风传统 / 实验创意),每个分类带真实数量角标;点击进入分类页。
- **标签筛选**:点击卡片/详情页上的标签回到首页按标签过滤。
- **卡片内容**:预览图(主体)+ 插件名 + 版本号(v1.0.0)+ 分类中文名 + 作者名。**没有**评分、下载量等未实现的统计。
- **真实目录统计**:页面显示"共收录 N 个风格化效果插件"(来自真实数据)。
- **加载/空/错误状态**:骨架屏、无结果空状态、目录源离线提示条、演示模式警示横幅。

### 4.2 插件详情页(第二核心页面)

- **主视觉区**:插件的"转换前 → 转换后"效果图对比**滑块**(用户最看重的功能:一张图上有一条可拖拽的分割线,左侧是原图、右侧是风格化后,带"前/后"角标;支持鼠标拖拽与键盘 ←→)。单图插件则直接显示大图。
- **元信息面板**(通常在右侧):插件名(中文大标题)、英文名、稳定的插件 ID(等宽小字,如 `huyangpahuo.mimi`)、作者(头像 + 用户名,链接到作者主页)、分类标签(链接到分类页)、版本号徽章。
- **操作区**:"下载安装包 .zip"主按钮(部分插件作者未上传打包文件时回退为源码压缩包)+ "在 GitHub 查看仓库"次按钮。
- **插件介绍**:中/英文介绍文字。
- **同类插件**:同分类的其他插件小卡片横排/网格。
- **评论区**(登录后可发):评论列表(头像 + 用户名 + 相对时间"3 天前" + 正文)、一级回复、删除自己的评论、底部"添加评论"输入框;未登录显示"登录后即可评论"引导。空状态:"还没有评论,来说点什么吧"。

### 4.3 分类页 / 作者主页

- 分类页:分类大标题 + 英文名 + 真实插件数 + 分类代码,下方是该分类的瀑布流。
- 作者主页:头像、显示名、用户名、简介、GitHub 链接(如已关联),下方是该作者全部已发布插件的瀑布流。

### 4.4 认证(参照典型的现代暗色登录页)

- 登录:邮箱 + 密码(可切换明文)、主色大按钮、分隔线、"使用 GitHub 登录"/"使用 Google 登录"描边按钮、忘记密码链接、注册跳转。
- 注册:用户名(3–20 位小写字母/数字/_/-,作为主页地址 `/users/用户名`)+ 邮箱 + 密码(4 段强度条)+ 确认密码;提交后进入"验证邮件已发送"面板。
- 找回密码 / 重置密码:独立页面,带成功/失效状态。
- 登录后:顶栏出现**用户菜单**(头像 + 下拉:发布插件 / 我的项目 / 账号设置 / 退出登录)。

### 4.5 发布流程(作者核心工作流)

新建项目表单字段:
1. 名称(中文)*、英文名(可选)
2. 项目标识 slug*(小写字母数字短横线,自动建议、可改;实时预览最终 ID = `GitHub用户名.slug`)
3. 分类*(下拉,20 个官方大类)
4. 初始版本(默认 1.0.0)
5. 标签(最多 3 个,回车添加的 chip)
6. 介绍(中文)*、英文介绍(可选)
7. **转换前效果图 \* / 转换后效果图 \***(两图必填,类型与 5MB 大小校验,带本地预览缩略图)
8. **打包 zip**(可选,≤20MB;不上传时下载回退源码包)
- 提交按钮:"创建项目并创建 GitHub 仓库"。
- 发布背后的机制(概念图不需要画,但文案会体现):自动在作者 GitHub 账号下创建/复用 `viora-plugins-hub` 仓库,自动写入 `plugin.json` 与 registry 条目;预览图与 zip 存进作者仓库。

### 4.6 我的项目(作者工作台)

- 列表:每行 = 插件名 + 状态徽章(已发布/已隐藏)+ 版本 + pluginId + 操作(查看详情 / 编辑 / 隐藏或发布 / **删除**)。
- 删除需输入插件名确认;删除仅移除站点记录并清理仓库内对应文件,作者 GitHub 仓库本身保留。
- 空状态:引导去新建项目。

### 4.7 账号设置

- 资料编辑:用户名、显示名、简介、头像 URL。
- GitHub 关联卡片:未关联 → "关联 GitHub"按钮 + 流程说明;已关联 → GitHub 头像 + 登录名 + 解除关联。
- 危险区(红调):注销账号——输入用户名确认后删除账号、资料、插件与评论(不可恢复;GitHub 仓库需自行处理)。

### 4.8 状态与提示体系(全站通用)

- 骨架屏(画廊/详情)、无结果空状态、404 页(全局 + 插件专属文案)、出错重试页。
- 警示横幅:目录源离线回退提示、演示模式警示。
- Toast 反馈(操作成功/失败)。

## 五、视觉现状与设计诉求(重设计的原因)

**当前视觉**(供了解,不是必须延续):极深炭色底 + 略亮一档的卡片 + 1px 细边框;紫罗兰作为唯一强调色(品牌标/CTA/焦点环);Space Grotesk 展示标题 + 无衬线正文;CSS columns 瀑布流。

**用户明确表示对当前界面不满意**,希望重新出概念稿。以下是可以自由发挥的方向,以及希望探索的气质:

1. **保持"作品是主角,UI 是暗房间"的画廊气质**——图片永远是视觉中心,UI 退后;但比当前版本更有设计感、更精致、更有记忆点。
2. 可以探索:更高级的暗色质感(如更细腻的层次、光感、留白节奏)、不同以往紫色系的强调方案、更有画廊/美术馆气质的排版、独特的卡片语言。
3. **必须保留的功能布局约束**:瀑布流卡片、详情页"左主视觉(滑块)+ 右元信息 + 下方评论"的信息架构、发布表单的字段完整性、搜索与分类的可达性。
4. **参考**:Pinterest 的浏览体验(瀑布流、懒加载、pin 详情页的评论交互)——只参考体验节奏,不抄视觉品牌。
5. **避免**:模板化 SaaS 后台风、廉价的紫色渐变堆砌、虚构数据(评分/下载量)。

## 八、最新设计方向增补(2026-10-25):Pinterest 式信息架构 + 公共讨论社区

用户已明确参考 **Pinterest 的桌面端界面**(提供了多张截图),要求按此重构信息架构,并新增公共讨论社区。

### 8.1 布局重构(替代顶部大导航)

- **左侧固定图标导航栏**(桌面端,约 64–72px 宽,深色):
  - 顶部:品牌 Logo
  - 中部图标(带选中态与悬浮提示):首页(画廊)/ 社区(讨论)/ 发布插件(+)/ 我的项目
  - 底部:账号设置(齿轮)+ 当前用户头像(点击展开菜单:个人主页 / 退出登录);未登录显示"登录"入口
- **顶部细搜索条**:仅剩全局搜索(不再放品牌与用户区),始终可见
- **移动端**:侧栏转为底部固定导航条(首页 / 社区 / 发布 / 我的项目 / 设置)
- 内容区获得更大宽度,页面重心下移到内容本身

### 8.2 新功能:公共讨论社区(公共讨论区)

- `/community`:讨论列表(卡片式:标题、正文摘要、作者、回复数、最后活跃时间;按最新排序)
- `/community/new`:发帖表单(标题 + 正文,登录必填)
- `/community/[id]`:帖子详情(正文 + 回复列表 + 回复输入框;作者可软删除自己的帖子/回复)
- 侧栏"社区"图标直达;与插件评论区共享"登录后可发言"的规则
- 数据:community_threads / community_replies(已建表,软删除,RLS 齐全)

### 8.3 详情页与个人主页的 Pinterest 对齐

- 详情页:大图居左占更宽,右侧操作栏(下载/GitHub/元信息)保持,评论区交互参考 Pinterest pin 详情
- 个人主页(`/users/[username]`):参考 Pinterest 个人页的"大标题 + 头像 + 统计 + 内容 Tabs"节奏(统计只展示真实数据:发布插件数;"收藏/图板"类功能暂未实现,不要画出)
- 通知/消息类图标(铃铛、私信):**暂未实现,概念图中不要出现**

### 8.4 本节替代冲突

第八节与第五节冲突处以本节为准;"避免清单"(模板化 SaaS 风、假数据)继续有效。
